# Explain the number

## When it applies

A report, a plan, or a decision contains a number: a count, a timing, a cost, a percentage.

## The rule

Say what the number counts, where it came from, and what it is compared with. When it moved, say why. A bare number invites the reader to guess its meaning.

## What it changes

- Report "load time 1.2 s" → report "median of five cold loads on the dev server, down from 2.0 s after removing the blocking script".
- Report "40 tests fail" → report which suite, on which commit, and how many failed before the change.

## Not this

Burying the number under method. Give the number first, then the one sentence that explains it.
