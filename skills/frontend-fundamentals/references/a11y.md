# Accessibility (a11y)

> Based on Toss frontend-fundamentals. Source: https://github.com/toss/frontend-fundamentals
> The normative standard is WCAG 2.2; each item is annotated with its success criterion (SC) number.

**Principle**: UI must be interpretable and operable via assistive technology (screen readers), keyboard, and touch. For **services where mobile sharing is core**, touch targets, image alt text, and semantic structure matter especially.

## 1. Semantic tags first (SC 4.1.2)

**Before** — a click-only `div`. Unusable by keyboard/screen reader.

```tsx
<div onClick={share}>Share</div>
```

**After**

```tsx
<button type="button" onClick={share}>
  Share
</button>
```

If you truly must attach `onClick` to a `div`/`span`, provide `role`, `tabIndex={0}`, and `onKeyDown` (Enter/Space) together. Prefer `button`/`a` whenever possible.

## 2. Image alt text (SC 1.1.1)

`next/image` **enforces `alt` at the type level**, so the real-world risk is not omission but **content quality** — judge not "is there an alt" but "does the alt convey the image's role".

```tsx
// Before — alt exists but conveys nothing
<Image src={photo.url} alt="image" width={400} height={300} />

// Before — an informative image misclassified as decorative; screen readers skip it entirely
<Image src={author.avatarUrl} alt="" width={40} height={40} />

// After — state what the image does
<Image src={author.avatarUrl} alt={`Profile photo of ${author.name}`} width={40} height={40} />
```

Only pure decoration (background patterns, images duplicating adjacent icons) keeps `alt=""`.

## 3. Color contrast (SC 1.4.3 / 1.4.11)

- Body text **4.5:1** or higher; large text (24px+, or 18.66px+ bold) **3:1** or higher.
- **Meaning-bearing UI components and graphics** like icons and borders also need 3:1+ (1.4.11).
- With a token system, contrast should already be guaranteed at the *token pair* level — the moment components pick colors individually, contrast verification multiplies per component.
- **Never convey state by color alone** (SC 1.4.1) — error/success is color + text/icon.

## 4. Keyboard focus (SC 2.4.7 AA / 2.4.11 AA / 2.1.2 A)

- **Never erase the focus ring.** Bare `outline: none` makes keyboard users lose their position. To customize, you **must provide a replacement style** via `:focus-visible`.

  ```css
  /* Before — keyboard users lose their position */
  .button:focus { outline: none; }

  /* After — hide the ring for mouse clicks, keep it for keyboard navigation */
  .button:focus-visible { outline: 2px solid var(--color-focus-ring); outline-offset: 2px; }
  ```

- Modals/drawers need a **focus trap** on open and **focus return to the trigger** on close (the counterpart of SC 2.1.2's no-keyboard-trap). Accessibility-primitive component libraries (Radix, React Aria, …) ship this by default — check the library behavior before hand-implementing.
- If the library renders a default close button and you add a custom one, the **focus order duplicates** — keep only one. Icon-only close buttons need `aria-label="Close"`.
- **Keep focused elements unobscured (SC 2.4.11 Focus Not Obscured).** When a sticky header, bottom CTA, or cookie banner covers a control reached by keyboard, the user cannot see their position even with a focus ring. Reserve space equal to the fixed element's height with `scroll-margin-block` on the scroll target (or `scroll-padding` on the container).

## 5. Reduced motion (SC 2.3.3 AAA)

Large motion causes real dizziness for users with vestibular disorders. Non-essential animation respects user settings. Being AAA it is not normatively mandatory, but the cost is near zero, so OMJ keeps it as the recommended default. Infinite animations without an auto-stop separately trigger **SC 2.2.2 (Pause, Stop, Hide), which is Level A**.

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

If an `/omj` spec's **Motion** section contains animation, specify this branch alongside it.

## 6. Mobile touch targets (SC 2.5.8 AA / 2.5.5 AAA)

- **AA minimum: 24×24 CSS px.** An exception applies when 24px spacing between target centers is secured (SC 2.5.8).
- **44×44+ recommended for primary mobile actions** — SC 2.5.5 (AAA), Apple HIG 44pt, and Material 48dp all land here.
- When the visual size cannot grow, widen only the hit area with `padding`.

## 7. Form labels and error announcements (SC 1.3.1 / 3.3.1 / 3.3.3)

```tsx
<label htmlFor="title">Title</label>
<input id="title" />
```

Errors shown **only visually** never reach screen-reader users.

```tsx
<label htmlFor="email">Email</label>
<input
  id="email"
  aria-invalid={Boolean(error)}
  aria-describedby={error ? 'email-error' : undefined}
/>
{error && (
  <p id="email-error" role="alert">
    {error}
  </p>
)}
```

- `aria-invalid` carries the state; `aria-describedby` **links the error message to the control**.
- Errors appearing asynchronously must live in a `role="alert"` (or `aria-live="polite"`) region to be announced.
- If your form library's `Field`/`Label` components auto-wire label–control–error links, check first and do not wire manually on top.

## smell → remedy

| Smell                                            | Remedy                                                        |
| ------------------------------------------------ | ------------------------------------------------------------- |
| Click-only `div`                                 | `button`/`a` or `role`+`tabIndex`+`onKeyDown`                 |
| Meaningless alt (`"image"`), misclassified `alt=""` | Describe the image's role (pure decoration only gets `alt=""`) |
| Body contrast under 4.5:1                        | Guarantee contrast at the token-pair level                    |
| Bare `outline: none`                             | Provide a `:focus-visible` replacement style                  |
| Sticky header covering the focused control       | Reserve space via `scroll-margin-block`/`scroll-padding` (2.4.11) |
| Ignoring reduced-motion settings                 | `@media (prefers-reduced-motion: reduce)` branch              |
| Unlabeled input                                  | `htmlFor`/`id` linkage                                        |
| State conveyed by color alone                    | Text/icon reinforcement                                       |
| Errors shown only visually                       | `aria-invalid` + `aria-describedby` + `role="alert"`          |
| Small touch targets                              | AA 24×24 (spacing exception); 44×44 recommended for primary mobile actions |

## Overengineering warning

- Spraying `aria-*` on every element makes screen readers noisier instead. Where semantic tags suffice, add no `aria`.
