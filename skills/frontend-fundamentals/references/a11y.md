# 접근성 (Accessibility, a11y)

> 토스 frontend-fundamentals 기반. 출처: https://github.com/toss/frontend-fundamentals
> 규범 기준은 WCAG 2.2를 따르고, 각 항목에 성공 기준(SC) 번호를 병기한다.

**원칙**: UI가 보조기술(스크린리더)·키보드·터치로도 해석·조작 가능해야 한다. **모바일 공유가 핵심인 서비스**라면 터치 타깃·이미지 대체텍스트·시맨틱 구조가 특히 중요하다.

## 1. 시맨틱 태그 우선 (SC 4.1.2)

**Before** — 클릭만 되는 `div`. 키보드·스크린리더 불가.

```tsx
<div onClick={share}>공유하기</div>
```

**After**

```tsx
<button type="button" onClick={share}>
  공유하기
</button>
```

`div`/`span`에 `onClick`을 붙여야만 한다면 `role`, `tabIndex={0}`, `onKeyDown`(Enter/Space)을 함께 제공한다. 가능하면 `button`/`a`를 쓴다.

## 2. 이미지 대체 텍스트 (SC 1.1.1)

`next/image`는 `alt`를 **타입 레벨에서 강제**하므로 실무의 진짜 리스크는 누락이 아니라 **내용 품질**이다 — 판정 기준을 "alt가 있는가"가 아니라 "alt가 이미지의 역할을 전달하는가"에 둔다.

```tsx
// Before — alt는 있지만 아무 정보도 주지 않는다
<Image src={photo.url} alt="image" width={400} height={300} />

// Before — 정보성 이미지를 장식으로 오분류해 스크린리더가 통째로 건너뛴다
<Image src={author.avatarUrl} alt="" width={40} height={40} />

// After — 이미지가 하는 일을 그대로 적는다
<Image src={author.avatarUrl} alt={`${author.name}님의 프로필 사진`} width={40} height={40} />
```

순수 장식(배경 패턴·아이콘 옆 중복 이미지)만 `alt=""`로 둔다.

## 3. 색 대비 (SC 1.4.3 / 1.4.11)

- 본문 텍스트 **4.5:1** 이상, 큰 텍스트(24px 이상 또는 18.66px 이상 bold) **3:1** 이상.
- 아이콘·경계선처럼 **의미를 전달하는 UI 컴포넌트와 그래픽**도 3:1 이상(1.4.11).
- 토큰 시스템이 있으면 대비는 *토큰 쌍*에서 이미 보장돼야 한다 — 컴포넌트마다 색을 새로 고르는 순간 대비 검증도 컴포넌트 수만큼 늘어난다.
- **색만으로 상태를 전달하지 않는다**(SC 1.4.1) — 에러/성공은 색 + 텍스트/아이콘.

## 4. 키보드 포커스 (SC 2.4.7 / 2.4.11 / 2.1.2)

- **포커스 링을 지우지 않는다.** `outline: none`만 두면 키보드 사용자가 현재 위치를 잃는다. 굳이 커스터마이즈하려면 `:focus-visible`로 **대체 스타일을 반드시 제공**한다.

  ```css
  /* Before — 키보드 사용자가 위치를 잃는다 */
  .button:focus { outline: none; }

  /* After — 마우스 클릭엔 링을 숨기고 키보드 탐색엔 남긴다 */
  .button:focus-visible { outline: 2px solid var(--color-focus-ring); outline-offset: 2px; }
  ```

- 모달·드로어는 열릴 때 **포커스 트랩**, 닫힐 때 **트리거로 포커스 복귀**가 되어야 한다(SC 2.1.2 키보드 트랩 금지의 짝). 접근성 프리미티브 기반 컴포넌트 라이브러리(Radix·React Aria 등)를 쓰면 기본 제공되므로, 직접 구현하기 전에 라이브러리 동작을 먼저 확인한다.
- 라이브러리가 기본 닫기 버튼을 렌더하는데 커스텀 닫기 버튼을 또 두면 **포커스 순서가 중복**된다 — 하나만 남긴다. 아이콘만 있는 닫기 버튼에는 `aria-label="닫기"`를 붙인다.

## 5. 모션 축소 (SC 2.3.3)

전정기관 장애 사용자에게 큰 모션은 실제 어지럼을 유발한다. 비필수 애니메이션은 사용자 설정을 존중한다.

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

`/omj` 스펙의 **Motion** 섹션에 애니메이션이 있으면 이 분기를 함께 명시한다.

## 6. 모바일 터치 타깃 (SC 2.5.8 AA / 2.5.5 AAA)

- **AA 최소: 24×24 CSS px.** 단 타깃 중심 간 24px 간격이 확보되면 예외가 인정된다(SC 2.5.8).
- **모바일 주요 액션은 44×44 이상 권장** — SC 2.5.5(AAA), Apple HIG 44pt, Material 48dp가 여기에 해당한다.
- 시각 크기를 키우기 어려우면 `padding`으로 히트 영역만 넓힌다.

## 7. 폼 라벨과 에러 안내 (SC 1.3.1 / 3.3.1 / 3.3.3)

```tsx
<label htmlFor="title">제목</label>
<input id="title" />
```

에러는 **시각적으로만** 표시하면 스크린리더 사용자에게 전달되지 않는다.

```tsx
<label htmlFor="email">이메일</label>
<input
  id="email"
  aria-invalid={Boolean(error)}
  aria-describedby={error ? 'email-error' : undefined}
/>
{error && (
  <p id="email-error" role="alert">
    {error}
  </p>
)}
```

- `aria-invalid`로 상태를, `aria-describedby`로 **에러 메시지를 컨트롤에 연결**한다.
- 비동기로 나중에 나타나는 에러는 `role="alert"`(또는 `aria-live="polite"`) 영역에 넣어야 낭독된다.
- 폼 라이브러리의 `Field`/`Label` 컴포넌트를 쓴다면 라벨-컨트롤-에러 연결을 자동 처리하는지 먼저 확인하고, 처리한다면 직접 배선하지 않는다.

## smell → remedy

| Smell                           | Remedy                                                     |
| ------------------------------- | ---------------------------------------------------------- |
| 클릭만 되는 `div`               | `button`/`a` 또는 `role`+`tabIndex`+`onKeyDown`             |
| 무의미한 alt(`"image"`)·오분류 `alt=""` | 이미지의 역할을 적는다(순수 장식만 `alt=""`)          |
| 본문 대비 4.5:1 미만            | 토큰 쌍에서 대비를 보장                                     |
| `outline: none`만 두기          | `:focus-visible` 대체 스타일 제공                           |
| 감속 설정 무시                  | `@media (prefers-reduced-motion: reduce)` 분기              |
| 라벨 없는 input                 | `htmlFor`/`id` 연결                                         |
| 색만으로 상태 전달              | 텍스트/아이콘 보조                                          |
| 에러가 시각적으로만 표시        | `aria-invalid` + `aria-describedby` + `role="alert"`        |
| 작은 터치 타깃                  | AA 24×24(간격 예외), 모바일 주요 액션은 44×44 권장          |

## 심화 감사

페이지 단위의 종합 UX/접근성 감사는 `web-design-guidelines` 스킬(외부 가이드 동적 fetch → `file:line` 리뷰)을 활용한다.

## 과설계 경고

- 모든 요소에 `aria-*`를 남발하면 오히려 스크린리더가 시끄러워진다. 시맨틱 태그로 충분한 경우 `aria`를 추가하지 않는다.
