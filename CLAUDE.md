# CLAUDE.md — oh-my-joy (OMJ) repository operating rules

Shared rules for Claude Code and Codex sessions; root AGENTS.md loads this contract in Codex. Keep it light every turn (<120 lines).

## What OMJ is

oh-my-joy (marketplace `omj`) is a standalone Claude Code and Codex plugin: **an adaptive, evidence-first workflow spine (headline: no proof, no done) with Figma-to-code as a first-class mode.** Claude exposes `/oh-my-joy:<name>` commands; Codex exposes matching `$oh-my-joy:<name>` skills. Every task enters `ultragoal`; small, safe work runs through a playbook with a check and a fresh review, and only risky or large work takes the planned spine: `deep-interview` (fuzzy) → `ralplan` → final Plan approval → `ultragoal` (native continuation, goal records, review, verify, resume). New PR creation stays in `ship`. Mental model: **"enter once, approve only risky or large work, and read one plain report."** Provider mapping, routing, and completion are canonical in `docs/EXECUTION-HANDOFF.md`.

## Documentation discipline (top priority)

When adding or changing a feature, update all of the following **together** (changing only code without the docs is incomplete):

1. **README** (usage; **EN `README.md` + KO `README.ko.md` in sync**) — command/flag/behavior changes and the "How to use OMJ" scenario map.
2. **CHANGELOG** (entry) — 1 change = 1 entry.
3. **docs/PRINCIPLES.md** (how it works — English, canonical) — whenever a principle, design decision, or mental model changes, including its opening decision table.
4. **evals/** — a behavior change in a command body adds or updates an eval case (`docs/EVALS.md`).

Canonical facts (workflow names and both hosts' `oh-my-joy@omj` install instructions) must **match across every doc and both README languages**. For narrative content, README is canonical (EN/KO in sync, same structure); other docs summarize/link.

## Command / agent / hook / style rules

- Single naming axis: every command uses an unprefixed kebab-case basename (`ralplan`, `verify`, `ship`, …) — an `omj`-prefixed basename is blocked by tests. In docs and the selector, use full host-native plugin names: `/oh-my-joy:<name>` in Claude Code and `$oh-my-joy:<name>` in Codex (bare plugin slash notation is test-enforced). Repo-local maintainer names follow their host discovery surface.
- Commands (6; details in README `## Commands`): `ralplan` (plan + critique gate) · `deep-interview` (interview → ralplan) · `verify` (proof report) · `ship` (verify → commit → PR, manual) · `ultragoal` (execute, resume) · `setup` (doctor, opt-in). Planned, not shipped: `/oh-my-joy:push` · `/oh-my-joy:ds-spec`.
- New command = `commands/<name>.md` + frontmatter `description`, `argument-hint`, `allowed-tools` (**least privilege**). Two test-enforced tiers: **zero-bash read-only** (deep-interview — no write tools, no Bash) / **report-only** (ralplan, verify — source-non-mutating, observation-scoped Bash). `Agent` on read-only commands is allowed only on ralplan, only for `critic`; ultragoal may dispatch implementation roles, and the test pins that the agent declares no write tools. `ship` may pre-approve only `git`/`gh`/`npx tsc` and never a test runner (its permission prompt confirms the evidence). Frontmatter `description`/`argument-hint` are English-first; Korean trigger examples may stay in parentheses — the language purity check covers bodies only.
- **Never declare a tool the body's procedure does not call.** Narrow Bash to the smallest runnable prefix (`Bash(npm i -g playwright-cli:*)`, not `Bash(npm:*)`). Declare MCP tools with the plugin prefix **and** the bare server variant side by side. Both are pinned by `tests/plugin-manifest.test.mjs`.
- **Prompt style** (`tests/prompt-style.test.mjs`): bodies follow the Anthropic prompting guide — state what to do and why, no shouted imperatives (MUST/NEVER/ALWAYS/…), at most 20 bold markers, no callout glyphs (the 🔴🟡🟢 severity triad excepted), no principle-number pointers, usage examples inside `<example>` tags. Bodies keep a compact skeleton: one goal sentence, numbered phases, rules with their reasons, an output contract.
- **Agents** (`agents/*.md`, exactly 3): `implementer` (approved spec required; frontend or general mode; inline executor and the teammate type for every Dispatch row — owns only its row's files, classifies blockers, reports evidence) · `design-qa` (inspect-only mechanical gate) · `critic` (read-only reviewer spawned by `ralplan` and `ultragoal` in a fresh context; one lens, a plain-language verdict line first; tools exactly `Read, Grep, Glob`, test-pinned). No `model` field (inherits). Agents are never listed as lanes. Rename grace: `figma-implementer` stays in the README migration table.
- **Surface tiers** (README canon): small, safe tasks run through a playbook inside `ultragoal`; planned work enters `deep-interview` (fuzzy only) → `ralplan` → approve → `ultragoal`; inside ultragoal each goal gets a helper verification and a `critic` review, a route gets `verify` browser mode and a fix loop inside the goal, and disjoint goals run as `implementer` teammates when Agent Teams are on; `verify` stays a standalone command; `setup` is occasional; agents/internal role skills are never normal entry points. Keep every doc telling that story for both hosts.
- **Output style** (`output-styles/oh-my-joy.md`): natural answers in the user's language (Korean rules ported from fluent-korean, credited in `NOTICE.md`), learner-friendly explanations, automatic approved handoffs. Codex setup copies the same body into project instructions (including existing overrides). `keep-coding-instructions: true`, never `force-for-plugin` — selected by the user via `/oh-my-joy:setup` or `/config` (test-enforced). Korean appears only inside its `<example>` blocks.
- **Hooks**: never ship `hooks/hooks.json` (auto-firing in every repo is the rejected alternative). Canonical scripts live in `templates/hooks/*.mjs`; `/oh-my-joy:setup` copy-installs them (opt-in); they no-op without an fe-context declaration. Codex uses the command-payload adapter and project registration template; native hook trust remains required.
- **HUD** (`hud/`): vendored statusLine bundle — never hand-edit `hud/vendor/hud/index.js`; regenerate per `hud/README.md`. Claude copy-installed user-globally by setup; Codex CLI uses native `tui.status_line`, while App has no custom HUD slot. Attribution: `NOTICE.md`.
- The SoT for workflow behavior is the matching Claude command plus the provider-neutral contracts in `docs/`; each Codex `skills/<name>/SKILL.md` is the host adapter. Keep both behaviorally aligned, with no Claude-only tool names in Codex skills. Codex requires the canonical `skills/` tree and model-discoverable skills; its 9 adapters declare both `user-invocable: false` and `disable-model-invocation: true` so Claude exposes only the 6 authoritative `commands/*.md`, while the shared `frontend-fundamentals` skill stays available on both hosts.
- **Gotchas**: `npm test` is scoped to `tests/*.test.mjs tests/hooks/*.test.mjs` (fixtures hold red suites); docs tests enumerate tracked files, so `git add` new markdown first; anchor CHANGELOG edits on `## [Unreleased]`; the legacy-token guard matches `\bomj-`. Eval-runner and self-application gotchas: `docs/EVALS.md` "Gotchas".

## Core design principles (summary — canonical: docs/PRINCIPLES.md)

- **Adaptive execution**: `docs/ADAPTIVE-EXECUTION.md` counts route facts — one deliverable, ≤5 files, no sensitive/contract/external change is the `playbook` route (no ledger, no question, one `critic` on edits beyond a ≤2-line single-file change, stop after three failing reviews); anything else plans; `docs/EXECUTION-CONFIG.md` resolves shared team preferences and capacity. Existing ledgers retain their review rules.
- **Plan-native primer**: `ralplan` and `deep-interview` are read-only; the interview automatically hands requirements to ralplan, which presents the final Plan. On the planned route nothing runs before approval.
- **Critique before consent**: `ralplan` challenges its draft — self-check always (decision record, simulated tasks, `ready` statement), plus exactly one `critic` for one pass when the plan has >2 target files, a shape change (breaking contract, dependency, OMJ contract, Figma section), or a risk; a finding still open shows on the approval card — and appends `## Critique` below it. Independence comes from a fresh context, never from another command. Approval is consent, not a feasibility check.
- **Approved plan carries the completion procedure**: after approval ultragoal implements each goal, records its helper verification and a fresh `critic` review (the diff handed as a file under `.omj/goals/<slug>/reviews/`), and for a goal with a verification route invokes `verify` browser mode and fixes within the goal — not implicit, because the user approved that section. Paid checks run once inside their goal and are not part of the final proof. `ship` is explicit for new PRs.
- **Ultragoal records**: `.omj/goals/<slug>/` stores the immutable approved brief, versioned goals, append-only ledger, and evidence. Only the leader uses `scripts/goal-state.mjs`; subprocess checks record actual exit codes and current workspace fingerprints. Final close requires final proof on the current fingerprint (run, or an identical stable pass reused through `reuse:true`) and independent review. A native goal completion alone is insufficient. Ledgers are schema v3 and v2 ledgers keep their rules.
- **Cross-host (opt-in)**: Effective `crossReview: preferred` from shared configuration runs every ultragoal review on the other host; the helper hashes the reviewer's own output file. When that host cannot run, it records a same-host review with its reason; it never falls back silently. A user message naming a lead-approved plan file starts ultragoal without re-planning. Canonical: `docs/CROSS-HOST.md`.
- **Resume**: same checkout and approved scope; preserve unrelated edits and native goals. Locks and expected revisions reject concurrent writers. No background-running promise when a native continuation surface is absent.
- **Library and reports**: `docs/principles/` (26 named principles, `INDEX.md` read at task start), `docs/playbooks/` (bug-fix, feature, refactor, investigation), and `docs/REPORTING.md` (five parts: Conclusion → Your move → What changed → Decisions made for you → How it was checked) are documents read on demand, never skills; bodies name the five parts in one sentence and point there. No fixed English report labels except the hook-read `evidence:` line.
- **Evidence rule**: on the planned route "done" needs `command · exit code · summary` plus the evidence kind (test report, command replay, browser capture); `verify` (evidence mode), `ship`, and agent-team teammates all record it. On the playbook route the report states each check in one line with its check strength (`docs/REPORTING.md`). Verification commands are never pre-approved.
- **Execution asks nothing**: between approval and the report the session asks no questions; blockers are `resolvable` (three approaches first) or `human-only` (stop, say what the user must do). Canonical in `docs/EXECUTION-HANDOFF.md`, test-pinned.
- **Three lanes, native**: inline · persistent goal · native parallel agents. Claude maps these to `/goal` and Agent Teams; Codex maps them to goals and native subagents. Both degrade to inline. OMJ owns the dispatch contract and a dependency-free goal-state helper, while the host owns continuous execution. No custom stop hook or external orchestrator is required.
- **Spec format**: uSpec sections + FF 4 criteria + a11y for frontend (plus a Design direction from the visual rubric for a new screen without Figma); goal/constraints/acceptance/verification commands for general work. Large Figma frames are read section by section.
- **Minimal bundling / borrow methodology, not surface**: one shared FF skill, six Codex workflow adapters, and three Codex internal role adapters; external methodologies are credited in `NOTICE.md`; rejected borrowings are recorded in PRINCIPLES.
- **Graceful degradation**: a missing figma/context7/playwright-cli/Agent Teams flag is a skip plus guidance, never an error.
- **Host parity**: every Claude surface has a Codex mapping in `docs/HOST-PARITY.md`; canonical loading, native discovery, hooks, and setup behavior are checked. `docs/CODEX-SETUP.md` owns the Codex setup mapping.
- **Measure, don't eyeball**: `evals/` (native `claude plugin eval`, `scripts/eval-runner.mjs` fallback) and the always-on token budget (`tests/token-budget.test.mjs`).

## Git / commits

- **No direct commits to main** — branch and open a PR to main. Release tags attach to the main commit after merge.
- Conventional commits: `<type>(<scope>): <subject>` (feat/fix/chore/docs/refactor/test).
- **Release**: Claude `/release` and Codex `$oh-my-joy:release` follow `docs/RELEASING.md`. Codex maintainer skills live in `.agents/skills/`, outside the plugin workflow list; the checklist diagnoses both installed hosts. Reuse explicit release authorization; never hand-edit versions, broadly stage, or manually tag. Before refreshing a local-directory marketplace, relocate every ignored or untracked non-runtime file the host would copy — list them with `git ls-files --others`, since `git status` hides ignored ones such as a session's `.claude/scheduled_tasks.lock` — or the installed cache hash will not match the Release.
- **Rename grace**: historical `goal-loop` maps to `ultragoal` without silently converting old state; the 2.0 removals (`sync`, `spec`, `review`, `fix`) map in the README migration table. Keep prior names in the migration table and CHANGELOG.
- ❌ **AI signatures, `Co-Authored-By: Claude`, "Generated with Claude Code" — never.**
- Write in English. Keep it concise.
- PRs: `pr-triage.yml` auto-assigns the maintainer and syncs the type label; still pass `--assignee`/`--label` explicitly.
