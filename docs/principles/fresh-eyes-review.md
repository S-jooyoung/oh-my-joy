# Fresh eyes review

## When it applies

Finished work that changed files needs a review before it is called done.

## The rule

Review it in a fresh context that did not write it. Hand that reviewer files, not conclusions: the user's request in its own words, the diff, and the list of new files. Do not tell the reviewer what to skip or how severe a finding may be.

## What it changes

- Reread your own diff and approve it → start a separate reviewer with the request, the diff, and the new-file list.
- Summarize the change for the reviewer → hand over the files and let the reviewer read them.

## Not this

Arguing with every finding. Fix what is wrong; when you disagree, report both positions instead of overruling the review.
